1. Product Overview

The platform lets merchants accept crypto payments using hosted checkout, payment links, APIs, and SDKs. Merchants can accept native tokens such as ETH, BNB, and MATIC/POL, or ERC20-compatible tokens by providing token addresses. The platform tracks payments on-chain, verifies them, sends webhooks, and provides dashboards, reporting, refunds, subscriptions, and enterprise operations.

Merchant Product

Dashboard, payment links, hosted checkout, API keys, webhooks, assets, wallets, reports, refunds.

Developer Product

REST API, Node SDK, React SDK, webhook verifier, test mode, testnet contracts, docs.

Payment Rails

Native and ERC20 payments on Ethereum, BNB Chain, Base, Polygon, and Arbitrum.

Business Model

Transaction fee, subscription SaaS plans, premium analytics, enterprise support, settlement/reporting fees.

- payment method = approve() + payToken()
- transfer source = transferFrom()

High-Level Payment Flow

1. Merchant creates payment through dashboard/API/SDK. 2. Backend validates chain, asset, wallet, amount, expiry, and merchant permissions. 3. Backend creates immutable payment record and returns checkout URL. 4. Customer opens checkout and connects wallet. 5. Checkout switches wallet to correct chain. 6. If ERC20: customer approves token and calls payToken(). 7. If Native: customer calls payNative() with msg.value. 8. PaymentRouter forwards funds directly to merchant minus fee. 9. PaymentRouter emits PaymentReceived event. 10. Chain indexer reads event after required confirmations. 11. Backend verifies event exactly against payment record. 12. Payment status becomes confirmed. 13. Webhook is signed and delivered to merchant. 14. Dashboard, reports, and analytics update.

7. Smart Contracts

Deployment Strategy

Deploy one PaymentRouter per chain. Keep the same ABI across all chains. Use a multisig as owner in production. The contract should not custody funds long-term; it forwards funds immediately to the merchant and fee recipient.

PaymentRouter.sol

// SPDX-License-Identifier: MIT
pragma solidity ^0.8.24;

import "@openzeppelin/contracts/token/ERC20/IERC20.sol";
import "@openzeppelin/contracts/token/ERC20/utils/SafeERC20.sol";
import "@openzeppelin/contracts/access/Ownable2Step.sol";
import "@openzeppelin/contracts/utils/Pausable.sol";
import "@openzeppelin/contracts/utils/ReentrancyGuard.sol";

contract PaymentRouter is Ownable2Step, Pausable, ReentrancyGuard {
    using SafeERC20 for IERC20;

    uint256 public constant BPS_DENOMINATOR = 10_000;
    uint256 public constant MAX_FEE_BPS = 300;
    address public constant NATIVE_TOKEN = address(0);

    address public feeRecipient;
    uint256 public feeBps;
    mapping(bytes32 => bool) public usedOrders;

    event PaymentReceived(
        bytes32 indexed merchantId,
        bytes32 indexed orderId,
        address indexed payer,
        address token,
        address merchant,
        uint256 grossAmount,
        uint256 feeAmount,
        uint256 netAmount,
        uint256 timestamp
    );

    event FeeUpdated(uint256 oldFeeBps, uint256 newFeeBps);
    event FeeRecipientUpdated(address indexed oldRecipient, address indexed newRecipient);

    error InvalidAmount();
    error InvalidMerchant();
    error InvalidFeeRecipient();
    error FeeTooHigh();
    error OrderAlreadyUsed();
    error NativeTransferFailed();

    constructor(address initialOwner, address _feeRecipient, uint256 _feeBps)
        Ownable(initialOwner)
    {
        if (_feeRecipient == address(0)) revert InvalidFeeRecipient();
        if (_feeBps > MAX_FEE_BPS) revert FeeTooHigh();
        feeRecipient = _feeRecipient;
        feeBps = _feeBps;
    }

    function setFeeRecipient(address newRecipient) external onlyOwner {
        if (newRecipient == address(0)) revert InvalidFeeRecipient();
        address oldRecipient = feeRecipient;
        feeRecipient = newRecipient;
        emit FeeRecipientUpdated(oldRecipient, newRecipient);
    }

    function setFeeBps(uint256 newFeeBps) external onlyOwner {
        if (newFeeBps > MAX_FEE_BPS) revert FeeTooHigh();
        uint256 oldFeeBps = feeBps;
        feeBps = newFeeBps;
        emit FeeUpdated(oldFeeBps, newFeeBps);
    }

    function pause() external onlyOwner { _pause(); }
    function unpause() external onlyOwner { _unpause(); }

    function payNative(
        bytes32 merchantId,
        bytes32 orderId,
        address payable merchant
    ) external payable nonReentrant whenNotPaused {
        if (merchant == address(0)) revert InvalidMerchant();
        if (msg.value == 0) revert InvalidAmount();
        if (usedOrders[orderId]) revert OrderAlreadyUsed();

        usedOrders[orderId] = true;

        uint256 feeAmount = (msg.value * feeBps) / BPS_DENOMINATOR;
        uint256 netAmount = msg.value - feeAmount;

        (bool merchantOk, ) = merchant.call{value: netAmount}("");
        if (!merchantOk) revert NativeTransferFailed();

        if (feeAmount > 0) {
            (bool feeOk, ) = payable(feeRecipient).call{value: feeAmount}("");
            if (!feeOk) revert NativeTransferFailed();
        }

        emit PaymentReceived(
            merchantId,
            orderId,
            msg.sender,
            NATIVE_TOKEN,
            merchant,
            msg.value,
            feeAmount,
            netAmount,
            block.timestamp
        );
    }

    function payToken(
        bytes32 merchantId,
        bytes32 orderId,
        address token,
        address merchant,
        uint256 amount
    ) external nonReentrant whenNotPaused {
        if (merchant == address(0)) revert InvalidMerchant();
        if (amount == 0) revert InvalidAmount();
        if (usedOrders[orderId]) revert OrderAlreadyUsed();

        usedOrders[orderId] = true;

        uint256 feeAmount = (amount * feeBps) / BPS_DENOMINATOR;
        uint256 netAmount = amount - feeAmount;

        IERC20(token).safeTransferFrom(msg.sender, merchant, netAmount);

        if (feeAmount > 0) {
            IERC20(token).safeTransferFrom(msg.sender, feeRecipient, feeAmount);
        }

        emit PaymentReceived(
            merchantId,
            orderId,
            msg.sender,
            token,
            merchant,
            amount,
            feeAmount,
            netAmount,
            block.timestamp
        );
    }
}

9. Multi-Chain Indexers

Indexer Manager ├─ Ethereum Indexer chainId=1 ├─ BNB Chain Indexer chainId=56 ├─ Base Indexer chainId=8453 ├─ Polygon Indexer chainId=137 └─ Arbitrum Indexer chainId=42161 Each indexer: - uses primary + fallback RPC - reads PaymentReceived logs - waits chain-specific confirmations - stores tx_hash + log_index idempotently - validates chainId, orderId, token, merchant, amount - marks payment confirmed or manual_review - enqueues webhooks and reporting events

Verification Rule

valid =
  payment.chainId === event.chainId &&
  payment.internalOrderHash === event.orderId &&
  payment.tokenAddress.toLowerCase() === event.token.toLowerCase() &&
  payment.merchantWallet.toLowerCase() === event.merchant.toLowerCase() &&
  payment.amountRaw === event.grossAmount.toString()

12. Risk, Compliance & Ops

Risk Controls

  • Token denylist and suspicious token detection.
  • Merchant daily/monthly volume limits.
  • Wallet risk scoring and blocked wallet list.
  • Velocity checks by payer, merchant, chain, and token.
  • Manual review state for mismatched or suspicious events.
  • Audit logs for all admin and merchant actions.

Operational Tools

  • Admin console for merchants, payments, tokens, chains, and risk reviews.
  • Support console for webhook retries and transaction investigation.
  • Manual payment status correction with dual approval.
  • Chain health dashboard with RPC/indexer lag.

13. Settlement & Reconciliation

MVP settlement is direct-to-merchant wallet. Production settlement adds reporting, exports, and optional partner-based fiat/off-ramp flows.

Reconciliation Jobs

Hourly: - check pending payments against chain - detect stuck webhooks - retry failed deliveries Daily: - compare payment_events with payments - generate merchant volume reports - generate fee reports - flag mismatched records Monthly: - merchant statements - tax/accounting exports - enterprise reports

Reports

  • Gross volume by chain/token.
  • Net merchant volume after fees/refunds.
  • Platform fee revenue.
  • Refund volume.
  • Failed/expired payment rate.

14. Observability

Metrics

  • Payment confirmation time by chain.
  • Indexer lag by chain.
  • RPC failure rate by provider and chain.
  • Webhook delivery success rate.
  • Queue depth and retry count.
  • Manual review queue size.
  • Checkout conversion rate.

Alerts

  • Indexer behind by more than threshold blocks.
  • RPC provider failure spike.
  • Webhook failure spike.
  • Payment confirmations delayed.
  • Database error rate or slow queries.
  • Contract paused/unpaused event.
